# 个人博客主页

一个轻量的个人网页：简洁卡片式布局 + 可真实播放的音乐播放器，支持白天/夜晚自动换肤、手机端自适应。

播放器固定 **3 首**歌，歌单直接写在 `script.js` 顶部，改起来就是改 3 行。

> **当前版本已修复「打开网页一直加载中 / 歌曲播放卡死」的问题**，具体原因见文末「历史问题：卡死是怎么修的」。

## 目录结构

```
person-site/
├── index.html          页面结构
├── styles.css          样式（含白天/夜晚两套配色）
├── script.js           交互逻辑（播放器 + 主题跟随 + 加载诊断）
├── check.html          部署自检页（打开就告诉你哪个资源没加载成功）
├── avatar.jpg          头像图片
├── qr.png              二维码图片
├── .nojekyll           让 GitHub Pages 跳过 Jekyll 处理，不要删
├── tools/
│   └── rename-to-ascii.sh   把音频文件名批量改成纯英文（可选）
└── music/              音频文件夹（当前 3 首）
    ├── azhe-gou-ai.mp3
    ├── djaxuan-pian-ai.mp3
    └── djshuxin-jia-bin.mp3
```

> 音频已改为**纯英文文件名**。歌名照常显示中文（靠 `script.js` 里的 `name` 字段），
> 只是磁盘上的文件名换成 ASCII，彻底避开 GitHub Pages 处理中文/括号文件名的坑。


## 快速开始

### 本地预览（推荐）

在本文件夹下开一个本地服务器：

```bash
python3 -m http.server 8000    # 方式一：Python
npx serve .                    # 方式二：Node
```

然后浏览器打开 `http://localhost:8000`。

> 也可以直接双击 `index.html` 打开，但浏览器在 `file://` 协议下会拦截本地音频。
> **音乐不播放就改用本地服务器方式** —— 页面顶部现在会直接把这句提示出来。

## 换歌

打开 `script.js`，改最上面的 `SONGS` 数组：

```js
const SONGS = [
  { name: "嘉宾（DJ舒心版）", artist: "DJ舒心", file: "djshuxin-jia-bin.mp3" },
  { name: "偏爱（咚鼓版）",   artist: "DJ阿轩", file: "djaxuan-pian-ai.mp3" },
  { name: "够爱（DJ版）",     artist: "阿泽",   file: "azhe-gou-ai.mp3" },
];
```

> `name` 是显示名，中文随便写；`file` 是磁盘上的真实文件名。
> 两者是分开的，所以文件用英文名不影响界面显示中文歌名。

三个字段的含义：

| 字段 | 说明 |
|---|---|
| `name` | 歌名，显示用，随便写，不影响播放 |
| `artist` | 歌手，显示用，同上 |
| `file` | **只写文件名**，不用带 `music/` 前缀。必须和 `music/` 里的实际文件名完全一致 |

换歌步骤：把新音频放进 `music/` → 把 `file` 改成新文件名 → 刷新页面。

想改成 4 首、5 首也可以，照着格式往下加就行，播放器会自动适配。

> **关于中文文件名**：脚本已经自动做了 URL 转义，中文、空格、全角括号都不用你操心，照抄文件名即可。

## 部署到 GitHub Pages

这是纯静态站点（无构建步骤、全部相对路径），可以直接托管。

### 网页上传（不用装 Git）

1. GitHub → 右上角 **+ → New repository**，仓库名填 `person-site`，选 **Public**，创建
2. 仓库页点 **Add file → Upload files**
3. 把 `person-site` 文件夹**里面的所有内容**拖进浏览器（直接拖文件夹会保留 `music/` 结构）
4. 填提交信息 → **Commit changes**
5. **Settings → Pages** → Source 选 **Deploy from a branch** → Branch 选 **main** + **/(root)** → **Save**
6. 等 1～2 分钟，访问 `https://你的用户名.github.io/person-site/`

### Git 命令行

```bash
cd person-site
git init
git add .
git commit -m "init"
git branch -M main
git remote add origin https://github.com/你的用户名/person-site.git
git push -u origin main
```

### 要注意的点

- 仓库体积约 **12 MB**（三首 mp3 占绝大部分）—— 远低于 GitHub「单文件 25 MiB」的限制，一次拖完即可
- `.nojekyll` 让 GitHub Pages 跳过 Jekyll 处理，**不要删**；上传时是隐藏文件，注意别漏掉
- 线上改歌：直接在网页上编辑 `script.js` 顶部那 3 行，或在 `music/` 里传新文件后改 `file`
- 部署完成后建议先打开 `/check.html` 自检一次，确认所有资源都能访问
- Git 会永久保留历史，以后删歌仓库也不会变小（这个体量完全无所谓）

## 换其他内容

### 头像 / 二维码

用同名文件覆盖 `avatar.jpg`、`qr.png` 即可（建议尺寸：头像 200×200，二维码 240×240）。

### 文字

打开 `index.html` 直接改：

| 位置 | 对应内容 |
|---|---|
| 顶部标题卡 | 「这是我的个人博客」 |
| 左侧卡片 | 我的简介 / 个人说明 / 联系方式 |
| 右侧卡片 2、3 | 励志语录、备用内容 |
| 底部通栏 | 版权信息 |

```css
:root {
  --bg: #f2f3f5;        /* 页面底色 */
  --card: #ffffff;      /* 卡片底色 */
  --text: #1a1a1a;      /* 主文字 */
  --active-fg: #2f6bff; /* 主题色（选中、播放器等） */
}
```

## 功能一览

### 音乐播放器
- 播放 / 暂停、上一首 / 下一首
- 点击列表任意歌曲即播放
- 进度条可拖动跳转，显示当前时间和总时长
- 列表自动显示每首歌的真实时长
- **音量控制**：拖动音量条调节，点击喇叭图标一键静音
- **随机播放**：开启后下一首随机跳转（不重复当前曲）
- **单曲循环**：开启后一曲播完自动重播
- 一曲播完自动播放下一首
- **记忆**：记住音量和上次听到哪首，下次打开自动选中（不自动播放）
- **系统媒体控制**：手机锁屏 / 通知栏显示歌名歌手，支持耳机线控
- **缓冲提示**：加载慢时播放按钮会转圈，不会以为点了没反应
- **加载诊断**：任何资源加载失败都会在页面顶部用中文写明原因，手机上不用开控制台也能排查
- 快捷键：空格键 = 播放 / 暂停

### 主题
- 自动跟随系统：系统深色 → 夜晚模式，系统浅色 → 白天模式
- 换设备、换时段都自动适配，无需操作

### 响应式
- 桌面：左侧简介 + 右侧三张卡片
- 手机：自动变单列堆叠，播放器保持左列表 / 右播放器并排

### 下雨效果（`rain.js`）
全屏 Canvas 装饰层，不挡任何点击，纯静态无依赖。真实感来自五层叠加：

| 层次 | 表现 |
|---|---|
| 天空雨丝 | 远层细而慢、近层粗而快，带横向风偏；落到页面底部会溅水花 |
| **卡片专属雨** | 每张可见卡片上方都有一小股雨在往下落，**保证每张卡片模块都被雨打到**（不只最顶上那张）；卡片越宽配得越多 |
| 打湿卡片 | 雨滴打在卡片哪就湿哪儿，留一块水渍再慢慢风干（会看到卡片逐渐被打湿） |
| 正面流水 | 水珠**长在卡片正面**，从落点往下流：起步黏滞、逐渐加速、被水渍绊住、轻微摆动、身后拖渐细水痕 |
| 水花 | 打中卡片上沿 / 正面 / 底边滴落都溅出受重力的细小水点 |

细节：
- 打中卡片**上沿**的水会沿上沿往两边铺开，再从边缘往下淌
- 打中卡片**左右边 / 底边附近**会额外补水，让它顺着边淌下去
- 水珠会被速度**拉长**（越快越细长、体积守恒），滑得快时身后还会**甩下更小的水珠**，形成玻璃上一串串的水路
- 滑到卡片**底边**会滴落，掉下去的水还会再落一小段形成"滴水"的尾巴
- 水珠盯住的是卡片上的**局部坐标**，所以页面滚动时它跟着卡片走，不会漂移
- 卡片圆角被单独处理，雨滴不会打在圆角外的空白上
- 跟随白天 / 夜晚主题自动换色，深色模式下水珠更亮
- 卡片滚出屏幕会清掉它的水渍状态，不占内存
- 单张卡片水渍、全屏水珠 / 水花 / 卡片专属雨都有数量上限，低端手机也不会卡

## 常见问题

**Q：页面一直"加载中"，或者点了播放就卡死？**
A：打开 **`https://你的用户名.github.io/仓库名/check.html`**，它会逐个检查所有资源并直接告诉你哪个出问题。

页面顶部也会自动出现橙色诊断条，不需要开控制台：

| 诊断条提示 | 原因 | 处理 |
|---|---|---|
| 提示 `file://` | 直接双击打开的 HTML | 用本地服务器或部署到 GitHub Pages |
| `音频加载失败：.../music/xxx.mp3` | 文件没上传成功，或文件名对不上 | 在仓库里点开 `music/` 确认文件在，名字和 `SONGS` 完全一致 |
| `格式不支持或文件损坏` | 上传过程中文件被截断 | 重新上传该 mp3 |
| `网络中断，文件可能没上传完整` | 传输中断 | 重新上传 |

最快的单点排查方式 —— 直接在浏览器地址栏打开那首歌的地址：

```
https://你的用户名.github.io/仓库名/music/azhe-gou-ai.mp3
```

能播放说明文件没问题；返回 404 就是没传上去或路径不对。

**Q：打包上传时要注意什么？**
A：把 `index.html`、`script.js`、`styles.css`、`check.html`、`avatar.jpg`、`qr.png`、`.nojekyll`
以及 `music/` 整个文件夹都传上去。**`.nojekyll` 必须传**，否则 GitHub Pages 会走 Jekyll 处理，
可能把文件名改坏。用网页拖拽上传时，直接拖整个文件夹能保留目录结构。

**Q：能自动播放吗？**
A：不能。所有现代浏览器都禁止页面在用户交互前自动出声，必须点一次播放按钮，这是通用限制。

**Q：歌曲时长一开始显示 `--:--`？**
A：页面在后台逐个读取音频的元数据，读完就会显示，通常一瞬间。
现在加了超时保护：某一首读不到（文件缺失 / 网络卡住）会自动跳过，**不会**把整个页面拖住。

**Q：想用中文文件名怎么办？**
A：可以，但不是首选。如果坚持用中文，务必**不要**混用全角 `（）` 和半角 `()`，
统一一种括号风格，并且文件名里的空格尽量去掉。改完记得同步改 `script.js` 的 `file` 字段。

## 历史问题：卡死是怎么修的

现象是「打开网页显示加载中，点播放就卡死」，根因有三个，都已修掉：

### 1. 页面一进来就顺序加载 3 个音频元数据，把主线程和带宽全占住

原代码 `scanDurations()` 一进页面就开始逐个探测每首歌的时长，而首个探测**没有超时保护**：

```js
// 修复前：一旦第一首读不到，就永远停在这一步
probe.onloadedmetadata = () => { /* 写时长 */ step(); };
probe.onerror = step;
probe.src = srcOf(SONGS[idx]);
```

只要第一个音频请求因为任何原因挂住（文件缺失、网络抖动、服务器不返回响应），
`step()` 永远不会被再次调用，页面就停在"加载中"的表象上。

**修复**：三重保险 —— 每首探测加 12 秒超时、整体加 90 秒总时限、并且推迟到 `window.load` 之后再跑，不和首屏资源抢带宽。

### 2. 中文 + 括号文件名在 GitHub Pages 上容易翻车

`DJ阿轩 - 偏爱 (咚鼓版).mp3` 同时包含中文、空格和**半角**括号，
而另外两首用的是**全角**括号。这种混用在 URL 编码后极易出现服务端找不到文件的情况。
`.nojekyll` 已保留（它能让 Pages 跳过 Jekyll 处理，避免特殊字符文件名被改坏）。

如果诊断条一直报某个文件 404，最省事的做法是**把音频改成纯英文名**：

```bash
# 例如
azhe-gou-ai.mp3
djaxuan-pian-ai.mp3
djshuxin-jia-bin.mp3
```

然后同步改 `script.js` 里的 `file` 字段即可，中文歌名照样显示（`name` 字段随便写）。

### 3. 错误信息只进了控制台，手机上看不到

原来的失败提示写死在播放器的副标题上，且没有兜底。
**修复**：新增页面顶部的诊断条，捕获阶段监听所有 `audio` / `img` 加载失败，
用中文写明「哪个文件、失败原因」，并区分网络中断 / 解码失败 / 文件不存在 / 格式损坏。
同时 `file://` 协议不支持 Range 的情况也会提前提示。
